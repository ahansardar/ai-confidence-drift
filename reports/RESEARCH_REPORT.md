# AI Confidence Drift Detection Using Machine Learning

**Organization:** PranavX Labs · **Domain:** Artificial Intelligence & Machine Learning
**Project Type:** AI/ML Research + Experimental Implementation

---

## 1. Abstract

AI models routinely output a confidence score alongside their predictions,
but confidence does not always track correctness. This project investigates
whether *changes* in a model's confidence — measured across a sequence of
related predictions — carry usable information about whether a given
prediction is reliable. A TF-IDF + Logistic Regression text classifier was
trained on a public two-class newsgroup dataset. Confidence *sequences* were
generated by feeding each test document to the model repeatedly under
increasing controlled corruption, producing real (not fabricated) confidence
trajectories. Statistical and drift-based features were engineered from these
sequences and used to train a second model — a confidence-drift detector —
that predicts whether a prediction is unreliable. Under a controlled,
document-level train/test split, confidence-drift features improved
unreliable-prediction detection F1 from 0.25 (no-confidence baseline) to
0.48, and ROC-AUC from 0.51 to 0.79. Calibration analysis (ECE = 0.153,
Brier = 0.125) shows the base model is only moderately calibrated, and 6% of
its high-confidence (≥0.75) predictions are wrong, including a 96%-confidence
error. The raw net drift of a sequence, however, only weakly correlates with
whether the final prediction is wrong (r ≈ 0.04) — it is the *shape* of the
confidence trajectory, not its endpoint change, that a learned detector can
exploit.

## 2. Introduction

Deployed ML systems are frequently trusted based on their reported
confidence. If confidence is unreliable, downstream decisions (auto-approving
a prediction, routing to human review, etc.) can silently fail. This project
treats confidence itself as a signal to be modeled, rather than assumed
trustworthy.

## 3. Problem Statement

A model's stated confidence is not guaranteed to reflect its actual
correctness probability. Confidence can be high and wrong, or drop for
reasons unrelated to correctness. There is no systematic method here, prior
to this project, for using confidence *changes across repeated predictions*
to flag likely-unreliable outputs.

## 4. Research Question

*Can Machine Learning detect significant changes in an AI model's confidence
and use those changes to identify potentially unreliable predictions?*

Sub-questions addressed:
- How stable is confidence across similar/perturbed inputs? (Section 11, 14)
- Does confidence decrease before incorrect predictions? (Section 14)
- Can confidence drift be used to predict prediction errors? (Section 13)
- Are high-confidence incorrect predictions detectable? (Section 15)
- Which features are most useful for detecting confidence drift? (Section 10, 13)

## 5. Hypothesis

**H1:** Statistical features derived from a confidence sequence (moving
average, volatility, consecutive decreases, deltas) predict whether the
associated prediction is incorrect better than the raw confidence value
alone, and far better than not using confidence at all.

This hypothesis is tested, not assumed — see Section 13 (Experiments) and
Section 15 (Results), including where it does *not* hold (e.g. net drift
alone is a weak predictor; see Section 14).

## 6. Related Work

This project draws on three established lines of ML research rather than
proposing new theory:
- **Model calibration** — the idea that predicted probabilities should match
  empirical frequencies (Guo et al., 2017, *On Calibration of Modern Neural
  Networks*; the reliability-diagram and Expected Calibration Error (ECE)
  methodology used here follows this line of work).
- **Selective prediction / misclassification detection** — using a
  classifier's own confidence to abstain from or flag unreliable predictions
  (Hendrycks & Gimpel, 2017, baseline softmax-confidence detection).
- **Robustness under input perturbation** — measuring how a model's output
  changes as input quality degrades is a standard way to probe reliability
  (e.g. adversarial/noise-robustness literature).

The specific contribution of this project is combining these: using
*sequential* confidence behavior under controlled perturbation, rather than a
single confidence value, as the input to a learned unreliability detector.

## 7. Dataset

- **Source:** `sklearn.datasets.fetch_20newsgroups` (public, scikit-learn's
  official mirror of the classic 20 Newsgroups corpus).
- **Task:** Binary text classification, `alt.atheism` (label 0) vs
  `soc.religion.christian` (label 1) — chosen because these two classes have
  overlapping vocabulary, which produces realistic (non-trivial) confidence
  variation rather than near-certain predictions.
- **Preprocessing:** headers/footers/quotes stripped (to avoid trivial
  leakage via metadata), empty documents dropped.
- **Size:** 1,754 documents total → 1,315 train / 439 test (stratified,
  75/25 split). Class balance: 44.4% / 55.6%.
- **Ground truth:** the newsgroup each post was posted to — a measurable,
  objective label, as required by the brief.

## 8. Methodology

### 8.1 Base classifier
TF-IDF (unigrams + bigrams, max 20,000 features, min_df=2) →
Logistic Regression (`max_iter=2000`). This is the "underlying prediction
model" whose confidence is subsequently studied — its own performance is
reported separately in Section 9/15 from the drift-detector's performance.

### 8.2 Confidence-sequence generation
The dataset has no natural repeated-measurement structure (each document is
labeled once). To obtain genuine sequential confidence data — the brief's
worked example of confidence dropping 0.94 → 0.59 across "predictions" — each
test document is corrupted at six controlled levels (0%, 10%, 20%, 30%, 40%,
50% of words removed, remainder shuffled) and re-classified at each level.
This produces a six-step confidence *history* per document (2,634 total
predictions across 439 documents), where every confidence value is a real
`predict_proba` output — none are fabricated or LLM-assigned. Corruption
seeds are derived deterministically (SHA-256 of the document ID) so the
pipeline is fully reproducible.

The ground-truth label is held fixed at the document's original label across
all corruption levels: the experiment studies how the *same underlying
sample* behaves as its signal degrades, not a relabeling exercise.

### 8.3 Feature engineering (see Section 10)

### 8.4 Confidence-drift detector
A second, separate ML classifier predicts a binary target — `unreliable`
(1 = incorrect prediction, 0 = correct) — from the engineered features. Three
feature sets (Experiments A/B/C, Section 13) and three algorithms (Logistic
Regression, Random Forest, Gradient Boosting) are compared.

### 8.5 Train/test protocol
All splits are performed at the **document level** (`GroupShuffleSplit`,
75/25), so that different corruption steps of the same underlying document
never appear on both sides of a split — this prevents the detector from
memorizing a document's outcome via a leaked sibling row.

## 9. ML Model

Base classifier and drift-detector model choices, per the brief's suggested
algorithm list:

| Component | Algorithms compared |
|---|---|
| Base text classifier | Logistic Regression (TF-IDF features) |
| Confidence-drift detector | Logistic Regression (baseline), Random Forest, Gradient Boosting |

Class imbalance in the drift-detector target (~21% unreliable) is handled
with `class_weight="balanced"` (Logistic Regression, Random Forest) or
equivalent `sample_weight` (Gradient Boosting, which has no native
`class_weight`) — a standard, non-fabricating methodological choice; without
it, F1 collapses toward 0 because models default to the majority class.

## 10. Feature Engineering

Investigated features, each computed only from information available up to
and including the current step (no leakage from future steps or the true
label):

| Feature | Description |
|---|---|
| `confidence` | current-step confidence |
| `prev_confidence` | previous-step confidence |
| `confidence_diff` | current − previous |
| `confidence_pct_change` | percentage change vs previous |
| `moving_avg_confidence` | cumulative mean up to current step |
| `moving_std_confidence` | cumulative std up to current step |
| `rolling_std_confidence` | std over a 3-step trailing window (volatility) |
| `confidence_range_so_far` | max − min confidence seen so far |
| `rate_of_change` | delta normalized by step index |
| `consecutive_decreases` | run-length of consecutive drops |
| `prediction_margin` | \|P(class 0) − P(class 1)\| |
| `historical_accuracy_for_class` | global step-0 accuracy for the predicted class (static, non-leaking) |
| `step`, `corruption_level` | position in the sequence |

Not every feature was assumed useful a priori — Experiment A/B/C (Section 13)
exists specifically to test whether the richer drift features add value over
single-point confidence, rather than including everything blindly.

## 11. Confidence Analysis

Confidence-vs-accuracy binning on step-0 (uncorrupted, i.e. real deployment)
predictions:

| Confidence range | # Predictions | Accuracy |
|---|---|---|
| 0–20% | 0 | — |
| 20–40% | 0 | — |
| 40–60% | 156 | 63.5% |
| 60–80% | 223 | 90.1% |
| 80–100% | 60 | 93.3% |

(No predictions fall below 50% because a binary softmax's max-class
probability is always ≥ 0.5.) Accuracy rises with confidence, confirming
confidence carries real signal — but the relationship is not perfectly
monotonic at fine granularity (see the 90–100% calibration bin in Section
12), so confidence alone is an imperfect reliability signal.

**Trend statistics across the 439 six-step corruption sequences:**
- Mean confidence: 0.663 (step 0) → 0.633 (step 5).
- 72.0% of documents show *net* confidence decrease as corruption increases;
  27.3% show a net *increase* (corruption can occasionally make text look
  more distinctively like one class, e.g. by removing ambiguous words).
- 0.7% show no net change.
- Correlation between net confidence drift and "became incorrect at the
  final step" is **r = 0.043** — very weak. **This directly tests, and
  rejects, the naive assumption that a decreasing confidence trend
  automatically means the model is becoming less accurate** (the brief
  explicitly warns against assuming this).

## 12. Calibration Analysis

Computed on step-0 (uncorrupted) test predictions.

- **Expected Calibration Error (ECE): 0.153**
- **Brier score: 0.125**

| Confidence bin | n | Avg. confidence | Avg. accuracy |
|---|---|---|---|
| 0.5–0.6 | 156 | 0.555 | 63.5% |
| 0.6–0.7 | 135 | 0.648 | 86.7% |
| 0.7–0.8 | 88 | 0.745 | 95.5% |
| 0.8–0.9 | 50 | 0.850 | 96.0% |
| 0.9–1.0 | 10 | 0.920 | 80.0% |

See `results/figures/reliability_diagram.png`. The model is under-confident
in the 0.6–0.9 range (accuracy exceeds confidence) but the top bin
(0.9–1.0, only 10 samples) shows *lower* accuracy than the 0.8–0.9 bin —
likely sampling noise given the small bin size, but also a genuine reminder
that very high confidence is not a guarantee, which motivates Section 13.

## 13. Experiments

Controlled comparison, identical document-level train/test split (1,974
train rows / 329 docs, 660 test rows / 110 docs), predicting whether a
prediction is `unreliable`:

| Experiment | Features | Algorithm | Accuracy | F1 | ROC-AUC |
|---|---|---|---|---|---|
| A — no confidence features | `step`, `corruption_level` only | Logistic Regression | 0.498 | 0.253 | 0.508 |
| B — single-point confidence | `confidence`, `prediction_margin` | Logistic Regression | 0.661 | 0.443 | 0.741 |
| C — confidence-drift features | full engineered set (13 features) | Logistic Regression | 0.705 | **0.483** | **0.787** |
| C — confidence-drift features | full engineered set | Random Forest | 0.726 | 0.472 | 0.752 |
| C — confidence-drift features | full engineered set | Gradient Boosting | 0.726 | 0.471 | 0.762 |

Full numbers (including confusion matrices and FPR/FNR): `results/metrics/drift_detector_experiments.json`.

**Finding: confidence-drift features provide a measurable, non-trivial
improvement** over both the no-confidence baseline (F1 +0.230, ROC-AUC
+0.279) and over single-point confidence alone (F1 +0.040, ROC-AUC +0.046).
This improvement is real and experimentally demonstrated, not assumed — it
is also modest in absolute terms (F1 ≈ 0.48, i.e. still far from a solved
problem), which is reported honestly rather than overstated.

## 14. Results

- The base classifier performs well on the primary task (81.1% accuracy,
  ROC-AUC 0.892) — see Section 15 for the full breakdown, kept separate from
  drift-detector performance as required.
- Confidence is informative on average (Section 11) but imperfectly
  calibrated (Section 12).
- Net confidence drift alone is a poor predictor of eventual incorrectness
  (r = 0.043, Section 11) — rejecting **H1** in its naive form.
- However, the *shape* of the confidence sequence (volatility, moving
  statistics, consecutive decreases, margin) — Experiment C — does carry
  real predictive signal for unreliability, supporting a more precise version
  of **H1**: it is the multi-dimensional shape of confidence behavior, not
  simple net drift, that helps.
- 6.0% of high-confidence (≥0.75) predictions were wrong; these account for
  7.2% of all errors (Section 15).

## 15. Error Analysis

**Underlying prediction model performance** (step-0, held-out test set, kept
distinct from the drift-detector as required):

- Accuracy: 0.811, Precision: 0.804, Recall: 0.873, F1: 0.837, ROC-AUC: 0.892
- Confusion matrix: `[[143, 52], [31, 213]]` (rows = actual, cols = predicted; class 0 = alt.atheism, class 1 = soc.religion.christian)

**High-confidence errors** (confidence ≥ 0.75, section 10 of the brief):
- 100 of 439 step-0 predictions (22.8%) were high-confidence.
- 6 of those 100 (6.0%) were incorrect — e.g. a document predicted as
  `soc.religion.christian` with **96.3% confidence** whose true label was
  `alt.atheism`.
- All six high-confidence errors in this run were the same failure direction
  (true label `alt.atheism`, predicted `soc.religion.christian`) — consistent
  with atheism-discussion posts that heavily quote or reference Christian
  scripture/terminology, which the TF-IDF+bigram representation cannot
  distinguish from genuine Christian-authored text. This is a plausible,
  inspectable cause rather than a black-box mystery, but has not been proven
  causal.
- These cases are exactly what confidence-drift detection targets: the
  confidence-drift detector (Experiment C) achieves 0.79 ROC-AUC at flagging
  unreliable predictions overall, but recovering *every* high-confidence
  error specifically is harder and is not separately guaranteed by this
  result — a limitation, not a claim of solved detection.

## 16. Limitations

- **Simulated sequences, not naturally repeated measurements.** Confidence
  "drift" here comes from controlled text corruption of the same document,
  not from genuinely independent repeated real-world queries. This is a
  documented, deliberate methodological choice (Section 8.2) to obtain real
  model outputs rather than fabricate a sequence, but it does not capture
  drift from other real-world sources (model updates, input distribution
  shift over time, etc.).
- **Small dataset.** 439 test documents (2,634 sequence rows) is modest;
  some bins (e.g. the 0.9–1.0 calibration bin, n=10) are too small for
  reliable conclusions on their own.
- **Two-class task.** Results may not generalize directly to multi-class or
  regression settings.
- **Single base-model architecture.** Only TF-IDF + Logistic Regression was
  studied as the underlying predictor; confidence behavior can differ for
  other architectures (e.g. deep neural networks tend to be over-confident
  in ways linear models are not).
- **Modest absolute detector performance.** F1 ≈ 0.48 for the best
  confidence-drift detector means most unreliable predictions are still
  missed or false-flagged; this is a real, improvable result, not a finished
  solution.
- **Document-level split reduces effective drift-detector training data**
  (1,974 rows from 329 documents) relative to the raw row count, by design,
  to avoid leakage — this is correct methodology but limits detector
  capacity.

## 17. Future Scope

- Apply the same methodology to a model architecture with different
  calibration behavior (e.g. a neural text classifier) to test whether the
  confidence-drift-features advantage generalizes.
- Use genuinely repeated real-world queries (e.g. same user question asked
  at different times) rather than synthetic corruption, if such data becomes
  available.
- Explore calibration techniques (temperature scaling, Platt scaling) to see
  whether improving base-model calibration changes the value added by
  drift-features.
- Extend to multi-class classification, where "confidence" and "margin"
  features are richer (e.g. top-2 margin, entropy of the full distribution).

## 18. Conclusion

Confidence, on average, correlates with correctness in this experiment (63%
→ 93% accuracy across confidence bins) but is not fully calibrated (ECE
0.153) and is not a safe absolute signal — 6% of high-confidence predictions
were wrong. Simple net confidence drift across a sequence is a weak predictor
of eventual error (r ≈ 0.04), but a learned detector using the *shape* of the
confidence sequence (volatility, moving statistics, consecutive decreases)
achieves a real, measured improvement in identifying unreliable predictions
over both a no-confidence baseline and single-point confidence (F1 0.25 →
0.44 → 0.48; ROC-AUC 0.51 → 0.74 → 0.79). This answers the research question
affirmatively but with an important qualification demonstrated experimentally
rather than assumed: confidence drift is useful when characterized by its
statistical shape, not by its raw net change alone, and even the best
detector here leaves substantial room for improvement.
